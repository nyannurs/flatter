# Flatter codebase audit (26 November 2026)

This is the plain-language audit of Flatter's code: what is good, what was wrong, what was removed, and what is still open. The technical record is in ADR-038 (`docs/decisions.md`). Every finding below was checked against the code, and in InDesign where it depends on InDesign's behaviour, before it was fixed.

## How big is it?

| Part | Lines |
|---|---|
| Line-breaking engine (`core`) | 1,937 |
| Hyphenation (`hyphenation`) | 954 |
| InDesign connection (`indesign-adapter`) | 3,960 |
| Panel (`panel`) | 1,548 |
| Simulator and playground (`simulator`, never shipped) | 674 |
| **Source code in total** | **about 9,070** |
| Tests that run on a computer without InDesign | 2,629 (220 tests) |
| Tests and measurements that run inside InDesign | 4,396 (60 scripts; 14 run as the test suite) |
| Documentation | 1,843 |

## What is good

- **Clean separation.** The line-breaking engine knows nothing about InDesign. It can be tested in seconds on any computer, and the same engine runs the browser playground. Only two files talk to InDesign.
- **Lots of tests.** Every change is checked by 220 quick tests and a suite of 14 tests inside a real InDesign, including a stress test of 27 layouts (images, right-aligned text, indents, drop caps, columns, spreads, special characters).
- **Decisions are written down.** 38 numbered decisions explain why things are as they are; a new developer (or another Claude) can continue without guessing.
- **Measured, not assumed.** InDesign's behaviour (how wide a character really is, where it allows a line break, how indents behave next to text wrap) is measured in throwaway documents and recorded in `docs/spike-results.md`.
- **Safe with your documents.** Everything Flatter changes can be undone in one step, removed with Remove, and survives saving and reopening.

## What was wrong (and is now fixed)

Ordered roughly by how likely you would have noticed.

1. **A preview on a few paragraphs changed the whole story.** It switched every paragraph to Flatter's settings, so a justified story became left-aligned everywhere. Now only the previewed paragraphs change.
2. **Special spaces broke the rag.** Flatter thought it could end a line at an em, en, thin or hair space; InDesign never does. Lines came out shorter than planned. Fixed by measuring what InDesign does.
3. **Page numbers in the text** (e.g. "see page 12") were measured as one digit, so on page 10 and later those lines lost a word. Fixed.
4. **Indent to Here** was not understood at all. Now supported.
5. **Your own soft hyphens** were refused in Preview but used by Apply to whole story, so the two gave different results. Fixed.
6. **Cmd+Z after a slider move**, then moving the slider again, could raise the pink alarm on every move. Fixed.
7. **A paragraph ending with a forced line break** never counted as finished, which made Preview slower. Fixed.
8. **Sentences ending in a short word** ("…kam er an.", "…said it.") were treated like abbreviations. Fixed.
9. **With "Align line ends exactly"**, in rare cases a line could end slightly past the edge. Fixed.
10. **Apply to whole story** could merge its work into something you did in between, and Cancel always said "Nothing was changed" even when that was not quite true. Now it stops cleanly and Cancel tells the truth.
11. **Undo in the wrong document**: if the automatic self-check failed, it could undo your last Flatter step in your own document. Fixed.
12. **Remove could fail completely** on one unusual setting. Now each setting is restored on its own.
13. **The panel**: sliders still worked while the whole story was being set (and their changes were lost); stored settings did not show for a story Flatter had set; reloading the panel left InDesign showing "Script context is not available anymore". All fixed.
14. Smaller ones: Remove matched paragraphs wrongly around empty paragraphs; "Rhythm across paragraphs" could break after a correction; hidden overflow lines were counted as mistakes; a few wrong messages.

## What was removed

- The **German / English buttons**: they only changed the dictionary language, which you assign in InDesign; Flatter already hyphenates each word in its own language.
- **Dead code** (functions and settings nothing used), an old copy of the panel bundle that could load by mistake, an unused build command, and a few one-off measurement scripts (their results are in the docs).

## Still open

- **Older InDesign versions:** decided, the minimum is now InDesign 2026 (0.7.0), the versions it was tested on.
- **Non-English InDesign:** decided, the README says it is tested on English InDesign. Flatter sets the composer by its English name; in a German-language InDesign this is untested.
- **Tabs and right indent tabs** are still not supported. Flatter reports them, does not raise an alarm, and gives the text back exactly; those paragraphs are just not set precisely.
- **Several Indent to Here characters in one paragraph** (a staircase) still work poorly; one per paragraph, the usual case, works.
- **Tidying the three longest files** (the panel, and the two InDesign files, 1,000–1,200 lines each) into smaller files: decided against for now. It would help an AI working on the code only moderately (the files can be read whole, and the tests catch mistakes), and it changes nothing for you.

## Compared with Adobe's guidance

Flatter follows the practices Adobe and experienced UXP developers recommend: heavy work runs as scripts InDesign completes at full speed, one undo step per action, only the permissions it needs, data stored in the document with namespaced labels, no reliance on panel show/hide events (which InDesign does not fire reliably), and the selection listener now cleans up after itself. Before a public Marketplace listing it would still need: testing in light and dark themes and on Windows, the versions question above, and a privacy and terms page.
